# 软件操作演示直播 · 操作手册

两端都是纯浏览器页面，媒体走 WebRTC（演示者 → TURN 中继 → 观看者），
不需要安装客户端，也不转码成 HLS。

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 演示者 | `/presenter.html?room=房间号` | 共享桌面、观察发送侧统计、手动干预清晰度、框选重点区域 |
| 观看者 | `/viewer.html?room=房间号` | 看画面、看端到端延迟与文字可读性、切换区域高清 |
| 演示素材 | `/fixture.html` | 自制验证页（细字代码 + 平滑滚动 + 动态图表 + 校准带） |

**图形入口**：日常使用只需要浏览器，两条链接即可，不需要命令行。
演示者与观看者之间的房间号用 URL 里的 `?room=` 对齐；`scripts/*.sh` 只是
把信令 / TURN / 验证素材起起来，属于辅助手段，不是使用直播功能的前提。

---

## 一、启动

```bash
./scripts/dev-up.sh        # 启动 Web 信令 + TURN 中继（后台，PID 写入 .run/）
./scripts/fixture-up.sh    # 可选：把验证素材铺满一块 1920x1080 的虚拟屏幕
```

- 服务起来后访问 `http://127.0.0.1:8080/presenter.html?room=DEMO`。
- `dev-down.sh` / `fixture-down.sh` 分别停止它们。
- 若只是手工试用，`fixture-up.sh` 可以跳过，共享你自己的任意窗口即可。

---

## 二、演示者操作流程

### 1. 加入房间
1. 打开 `presenter.html`，确认「信令」标记变为已连接（页面顶部）。
2. 房间号默认 `DEMO`，与观看者约定一致即可。
3. 点「加入房间」。此时状态为 `ready`——**尚未共享任何画面**，
   观看者会看到「演示者尚未共享」，不会看到黑屏当直播。

### 2. 开始共享
1. 点「开始共享」，在弹出的浏览器选择框中选择：
   - 整个屏幕（推荐，文字最清晰、最接近真实演示）；
   - 或某一个窗口 / 浏览器标签页。
2. 采集建立后状态变为 `live`。页面顶部「采集」会显示实际采集尺寸与帧率，
   例如 `采集：monitor 1920x1080@15`。
3. 左侧是本地预览。**注意：预览尺寸恒定不变**，清晰度调整发生在采集约束、
   轨道帧率和发送端编码参数上，不会靠缩小预览来"看起来变差"。

### 3. 共享过程中的自适应
右侧「自适应清晰度」面板会持续刷新：

- **当前档位**：2160p → 360p 共 9 档，每档绑定一个分辨率和一个码率上限。
- **BWE 估计**：来自传输层拥塞控制（`availableOutgoingBitrate`），
  经过中值滤波 + 非对称 EWMA + 斜率限制，单次尖峰不会触发跨档跳变。
- **帧率**：由画面变化面积决定，静止文档 2fps、滚动 15fps、大范围动画 30fps、全屏快速动画最高 60fps。
  变化面积按 16×9 网格统计（本轮实测：静止约 5–6%，滚动约 32%），
  各档之间有上下行不同的阈值（滞回），避免在边界来回跳。
- **试探升档**：带宽恢复后不会直接拉满。面板会先显示「试探升档至 576p」，
  在目标档位上观察约 8 秒，确认链路承受后才提交；失败会回退并延长观察期。
- **事件日志**：降档、试探升档、到达清晰度下限都会留下带时间的记录。

厂商/浏览器给的选择框之后，如果中途关闭了共享来源（例如关掉了被共享的窗口），
**轨道会结束**，页面立刻进入 `ended`，不会把最后一帧继续当成直播。

### 4. 切换共享源
点「切换共享源」会重新弹出选择框：

- 选择框弹出期间状态为 `switching-source`，观看者端显示「演示者正在切换共享源」，
  并**清除旧画面**，避免把切换前的最后一帧误认为新内容。
- 选到新来源后自动用 `replaceTrack` 替换，不需要重连。
- 在选择框里点「取消」会回到切换前的状态，直播不中断。

### 5. 结束
点「结束共享」→ 状态 `ended`，两端的旧画面都会被清除。观看者看到
「直播已结束 · 最后一帧已清除，不再代表实时画面」。

### 6. 演示者的辅助控件
- 「手动降一档 / 手动升一档」：在自适应之外强制改档，用于现场演示对比。
- 「重置自适应」：清空估计窗口与冷却计时，重新开始收敛。
- 观看者列表：显示每个观看者的连接状态。

## 三、重点区域模式（清晰度优先）

默认的「整屏」策略原样保留，可随时切回；重点区域是**叠加**在整屏之上的
可选项，不是替换。它同时保留整屏轨道（观看者仍能看到选区在屏幕上的位置）
和一条只包含选区的额外轨道。

### 1. 演示者：框选并发送

1. 先「开始共享」，让预览里出现要讲的内容。
2. 把「屏幕直播模式」切到「重点区域（整屏位置关系 + 区域高清）」。
3. 点「框选重点区域」，在左侧预览上拖拽出代码区或图表区；**释放即生效**，
   不需要再点一个「开始」。
4. 面板会显示实际在做的事：

| 字段 | 含义 |
| --- | --- |
| 选区（源像素） | 框选落在**共享源原生像素**上的矩形 |
| 区域编码尺寸 | 实际送给编码器的尺寸（通常与选区相同，即不放大） |
| 覆盖完整度 | 选区有多少真正落在共享源内；低于 100% 会按源边界裁剪 |
| 同类区域整屏像素 | **同一个位置**在全屏轨道里得到多少像素（用当前全屏编码尺寸换算） |
| 细节倍率 | 区域编码像素 / 全屏为同一内容分配的像素，取平方根即线性倍率 |
| 区域码率 / 帧率 / 队列延迟 | 只统计区域这条 m-line 的实测值 |

5. 若窗口被移走、页面滚动或来源切换导致选区不再覆盖内容，面板会报
   「区域内容已失去细节」并**暂停区域轨道**（不再发送已经移出选区的内容）。
   内容回到选区下方时轨道会自动恢复；如果窗口挪走不回来了，点「框选重点区域」
   重新校准即可。

### 2. 能力与实现方式

- 浏览器支持 `MediaStreamTrackProcessor` 时，采用**独立区域轨道**：
  从整屏采集帧里按源矩形裁剪 → 画到 canvas → `captureStream(0)` 生成轨道 →
  经预协商的第二条视频 m-line 用 `replaceTrack` 发送。
- 不支持时退化为受控的裁剪编码路径，页面会在「引擎」字段里标明实际用的是哪种。
- 两种路径都**不做"把低分辨率纹理放大"冒充清晰度**：区域轨道按源像素编码，
  面板里的细字之所以更清楚，是因为它拿到的就是原生像素，不是因为被放大。

### 3. 观看者：接收与切换

- 打开 `viewer.html?room=房间号`（带 `?region=1` 时直接进入区域视图）。
- 面板「重点区域」区可点「接收重点区域 / 只看整屏」切换。
- 切回整屏时，区域接收轨会被**停掉并清零**，不再占用带宽；
  再切回区域会重新接上已经协商好的那条 m-line，不会新建连接。
- 若演示者尚未框选，观看者看到「演示者未选择重点区域」，不会显示旧画面。

### 4. 异常提示

演示者面板的「重点区域」区、观看者面板的「重点区域」区都会显示下列异常：

| 代码 | 含义 |
| --- | --- |
| `no-selection` | 已切到区域模式但还没框选 |
| `region-outside-source` | 选区完全落在共享源之外，区域轨道已停止发送 |
| `region-clipped` | 选区部分在源外，已按源边界裁剪（不会采集范围外内容） |
| `region-too-small` | 裁剪后低于可读下限 |
| `region-content-lost` | 选区内容丢失，已暂停区域轨道 |
| `region-stalled` | 有观看者请求区域，但没有区域帧被编码 |
| `region-bandwidth-limited` | 区域编码受带宽限制 |
| `region-downscaled` | 实际编码尺寸低于原生裁剪（清晰度已打折） |
| `region-queue` | 区域发送队列延迟过高，编码器可能跟不上 |
| `total-over-estimate` | 整屏 + 区域合计接近可用带宽，整屏档位可能因此下调 |

### 5. 实测结论（回归例 `--scenario region`）

一次完整运行（`evidence/region-final/`）的实测结果：

- 区域轨道 902×430，全屏轨道在同样位置只分到 901×430（全屏此时编码 1920×1080），
  即该窗口内没有放大、没有裁剪损失。
- 带宽：仅整屏 4192 kbps；整屏 + 区域 4954 kbps，区域本身 762 kbps，
  **总成本 ×1.18**（都是 `outbound-rtp bytesSent` 的实测值，不是设定的码率上限）。
- 把全屏压到 504p（实际编码 1024×576）、换成高密度字形后，
  同一块内容在区域里 detail=2.21，在全屏里 detail=1.72，**×1.29**
  （两者都先重采样到同样的 720 宽再比，所以不是"像素多就赢"）。
- 选区内的红色标记出现在接收画面里（偏移 0.032 个裁剪宽度），
  选区外 60px 的标记没有出现 —— 证明收到的就是框住的那块内容。
- 移出内容后区域轨道暂停、字节不再增长，移回后自动恢复；
  采集尺寸从 1920×1080 缩到 1280×720 时选区重新投影为 601×287；
  观看者切回整屏后区域字节增量归零；复杂重选只保留一条区域 m-line。

## 四、观看者操作流程

1. 打开 `viewer.html?room=房间号`（演示者页面的「复制观看链接」可直接复制）。
2. 点「加入观看」。状态依次为
   `connecting` → `requesting` → `connecting-media` → `live`。
3. 顶部四个标记分别显示：

| 标记 | 含义 |
| --- | --- |
| `● 直播中` | 正常接收中 |
| `分辨率` | 当前**实际解码**的分辨率（来自接收统计，不是期望值） |
| `解码 fps` | 实际解码帧率 |
| `延迟 p50/p95` | 端到端延迟，由画面内的编码时间戳与本地时钟求差 |

4. 右侧面板分区：
   - **发送/接收统计**：帧数、丢包（累计值与本窗口丢包率）、抖动、可用带宽、
     传输路径（候选对类型，例如 `relay → relay`，即媒体确实经 TURN 转发）。
   - **端到端延迟**：p50 / p95 / 最大值 + 直方图，每帧呈现时采样一次。
     面板里的数字覆盖**整场会话**（现场观看时稳定、不跳），
     所以它不会随网络阶段快速变化；实验报告里的逐阶段延迟改用最近 5 秒窗口，
     两者的区别见[弱网报告](weak-network.md#二基线无损伤)。
   - **文字可读性提示**：对固定文本区域算 Laplacian 方差（锐度）
     和深色像素占比（墨量），并给出可读性提示；同时显示校准带解码成功率。
     这两项是**实时提示**，会随帧变化跳动；报告里用的是保存下来的
     同区域裁剪图，因为滚动平均在分辨率切换时会混入不同档位的样本。
   - **校准带解码**：最近解出的时间戳 / 滚动位置 / 模式 / 序号。
   - 「保存对比画面」：把观看者当前**实际接收**帧的全景图、校准带、文本区域
     存到 `evidence/<run>/`（未带 `?run=` 时存到 `manual`），用于事后对比。

5. 断线/异常时的状态（**都不会保留旧帧冒充直播**）：

| 状态 | 触发条件 | 观看者看到 |
| --- | --- | --- |
| `permission-denied` | 演示者在选择框点了取消 | 「演示者已取消屏幕权限」，清空画面 |
| `capture-failed` | 采集本身失败（无轨道等） | 「演示者采集失败」 |
| `source-switching` | 演示者正在重新选择来源 | 「正在切换共享源」，清空画面 |
| `ended` | 演示者主动结束或轨道结束 | 「直播已结束」，清空画面 |
| `signal-lost` | 与信令服务器断开，或演示者 socket 掉线 | 「与服务器断开 / 信令连接已断开」，清空画面 |
| `frozen` | 仍在直播但 1.5 秒没有新帧 | 保留画面但盖「画面已暂停更新」角标 |

`frozen` 是唯一保留画面的状态，而且明确标注当前不是实时画面；
其余所有状态都会把 `srcObject` 置空。

## 五、弱网实验操作

实验由 `scripts/experiment.mjs` 驱动：它会打开真实的演示者与观看者页面，
通过 TURN 中继的整形接口注入带宽 / 时延 / 抖动 / 丢包，并逐秒采样两端。

```bash
./scripts/dev-up.sh
./scripts/fixture-up.sh
node scripts/experiment.mjs --scenario all --run my-run
```

结果写入 `evidence/my-run/`：

- `baseline.json` / `motion.json` / `congestion.json` / `states.json` / `floor.json` / `region.json`
- 每个场景的 `*-presenter-full.png`、`*-viewer-full.png`
- 同一区域的 `*-strip-*.png`（校准带）与 `*-text-*.png`（文字区域）
- 重点区域场景另存 `region-*-viewer-region.png`（收到的区域画面）、
  `region-highdensity-viewer-full-samecrop.png`（同一块内容在全屏里的样子）等

单独跑某个场景：

```bash
node scripts/experiment.mjs --scenario congestion --run weaknet
node scripts/experiment.mjs --scenario region --run region-run   # 重点区域回归
```

重点区域回归会依次验证：框选对应关系（含选区外标记不外泄）、高密度字形下的
清晰度/带宽实测、采集尺寸变化后的坐标重投影、窗口移走后暂停与恢复、
选区越界裁剪、观看者切回整屏后的字节归零、快速重选只留一条 m-line、
来源关闭后的清理。跑完后用 `node scripts/report.mjs evidence/region-run`
打印「focus region」一节。

手动做弱网对比时，可直接调中继整形接口：

```bash
curl -s -XPOST http://127.0.0.1:3479/shape \
  -H 'content-type: application/json' \
  -d '{"upKbps":300,"downKbps":300,"delayMs":60,"jitterMs":25,"lossPct":1}'
curl -s -XPOST http://127.0.0.1:3479/reset   # 恢复
```

`GET /state` 可以读到整形器的实际吞吐、排队时延和丢弃计数，
用来判断"是链路真丢包"还是"我们自己的发送队列堆了"。
